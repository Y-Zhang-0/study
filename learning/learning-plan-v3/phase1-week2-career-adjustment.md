## 执行原则

本细排覆盖 Phase 1 Week 2 的 D9-D14 执行方式。官方 `daily-schedule.md` 仍是日历骨架；本文件是 D9-D14 的转岗强化执行依据。

- 每日任务按转岗能力设计，标称 2h/8h 只作为负荷控制参考，不作为降低深度的理由。
- 每天必须包含：工程产出、机制深挖、边界坑、面试迁移、可验证结果。
- D9-D14 围绕同一个 React + TypeScript 笔记/待办 SPA 连续演进，避免孤立 API 示例。
- 教学示范遵守“同构不同题”：示范用不同业务对象和函数，作业保留迁移手写空间。
- 若当天内容过大，拆为“今日必达”和“滚动补强”，不能把核心内容降成浅层清单。
- 转岗需求优先级最高；原计划内容能服务转岗目标就继承并加深，不能服务时可以调整、替换、合并或延后，但必须说明取舍理由并保留可验证产出。

## D10：React 核心与项目骨架

| 维度 | 内容 |
|:--|:--|
| 主题 | JSX、函数组件、props、state、事件、列表渲染，对比 Vue |
| 今日必达 | 建立 React + TS 子项目；实现笔记/待办列表的只读展示 + 新增表单雏形 |
| 工程产出 | `phase1/react-study/`：Vite React TS 项目骨架、基础组件拆分、类型化 props |
| 机制深挖 | JSX 是函数调用表达式，不是模板；React 通过 state 触发重新渲染 |
| 边界坑 | 直接修改数组/对象 state 不触发可靠更新；列表 key 不能随便用 index |
| 面试迁移 | “React 与 Vue 在模板、响应式和数据流上的核心差异？” |
| 验证 | `npm run typecheck` / `npm run build`；浏览器手测新增交互 |

## D11：Hooks 与副作用

| 维度 | 内容 |
|:--|:--|
| 主题 | `useState` 进阶、`useEffect`、依赖数组、清理函数、`useRef`、`useMemo` |
| 今日必达 | 给 SPA 加 localStorage 持久化；抽出一个持久化或列表操作 Hook |
| 工程产出 | `useLocalStorage` 或同等自定义 Hook；刷新后数据不丢 |
| 机制深挖 | render 闭包与陈旧闭包；依赖数组为什么会导致无限循环或旧值问题 |
| 边界坑 | effect 中 setState 引发循环；漏依赖导致读到旧状态；定时器/订阅不清理 |
| 面试迁移 | “`useEffect` 依赖数组怎么判断？”“什么是陈旧闭包？” |
| 验证 | 构建通过；手测刷新保留数据；手动制造错误依赖观察问题 |
